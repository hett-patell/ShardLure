# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ShardLure derives **attacker identity** from SSH honeypot telemetry. It wraps the [Cowrie](https://github.com/cowrie/cowrie) SSH honeypot (a separate Python process), ingests Cowrie's JSON log + journald sshd lines, clusters attackers into **actors**, enriches their IPs against threat-intel feeds, and serves a live dashboard + forensic TUI. It also shares findings back out (MalwareBazaar payloads, AbuseIPDB reports, STIX IOCs).

Single Go module: `github.com/networkshard/shardlure` (Go 1.27). One binary, subcommand-dispatched from `cmd/shardlure/main.go`.

## Commands

```bash
make build          # go mod tidy && go build -o shardlure ./cmd/shardlure
make test           # go test ./...
make fuzz           # opt-in fuzzing of the 3 attacker-input parsers (FUZZTIME=5m to extend)
go test ./internal/store/ -run TestName   # single package / single test
go vet ./...        # CI runs this; keep it clean
```

**Fuzz targets** cover the three parsers that eat attacker-controlled bytes: `journal.FuzzParseLine`, `cowrie.FuzzParseReader`, `capture.FuzzDecodeTTYReader` (the packed `<iLiiLL` TTY struct — sharpest edge, since its own length arithmetic could over-read). CI does **not** fuzz, but `go test ./...` runs each target's seed corpus, so known-bad inputs stay covered. Only *failing* inputs get written to `testdata/fuzz/`, and those files are binary — don't commit them (`check-utf8.sh` would reject them); pin the finding as a readable unit test instead, as `TestParseLineSanitisesInvalidUTF8AndNUL` does.

CI (`.github/workflows/ci.yml`) runs on push to `main`, tags `v*`, and all PRs: `check-utf8.sh` → `go mod verify` → `go vet` → `go test -coverprofile` → build → `version` smoke → `ci-web-smoke.sh` (boots the web server and checks it serves). Then a cross-build job. There is **no separate lint step** beyond `go vet`; do not add one without asking.

Run locally after building:
```bash
./shardlure ingest journal testdata/sample.journal --replace   # see make run-sample
./shardlure ingest cowrie <cowrie.json> --replace
./shardlure actors [--limit=N]
./shardlure reclassify cowrie [--dry-run]   # re-derive playbooks from persisted aggregates
./shardlure actor show <ip|actor-id>
./shardlure web :8080 [--tailscale]        # dashboard only, static DB
./shardlure live :8080 --cowrie=<path>     # live ingest loop + dashboard (the real daemon)
./shardlure dashboard                       # forensic TUI (tui/app.go, bubbletea)
```

## Deploy workflow — the two non-obvious gotchas

1. **Never `scp` Go/Python sources to the VPS — it silently corrupts them to UTF-16.** Use `make deploy` (`scripts/push-sources.sh`, tar-over-SSH). CI enforces this with `scripts/check-utf8.sh`, which fails the build on any tracked file with a UTF-16 BOM or NUL bytes. If sources arrive mangled, `scripts/fix-go-sources.sh` / `scripts/repair-text.sh` repair them. This is why the check exists — respect it.

2. **Two independent installers, with inverted port defaults.** `scripts/install.sh` downloads a prebuilt release binary (no Go toolchain). `scripts/shardlure.py run` is the richer VPS wrapper: installs Go, *builds* from source, and does the interactive real-SSH-port migration. Their honeypot/admin port defaults are swapped — `shardlure.py` puts the honeypot on **22** and moves real sshd to **2222** (key-only); `install.sh` keeps admin on 22 and the honeypot on 2222. `sudo ./shardlure run` execs into `scripts/shardlure.py run`.

## Architecture

Data flows in one direction, and `pkg/models` (`Event`, `Actor`, `AggregatedActor`, `IPStat`, the `Kind*`/`Source*` consts) is the shared vocabulary that lets `store` and `actor` avoid an import cycle:

```
Cowrie :22 → cowrie.json ─┐
                          ├→ ingest → []Event → cluster → Actor → SQLite → web :8080 / TUI
journald sshd  ───────────┘                                          ├→ enrich (inbound IP rep)
                                                                      └→ share/report (outbound intel)
```

The Go binary and the Cowrie process are **separate systemd units with no IPC** — the only contract between them is the JSON log file on disk (`$DATA_DIR/cowrie/var/log/cowrie/cowrie.json`). `shardlure-live.service` `Wants=cowrie.service`.

### The live daemon is the conductor (`cmd/shardlure/main.go` `cmdLive`)
Seeds history, then runs **five background goroutines** + the web server (main goroutine), all sharing one `*store.Store` and one `*settings.Keystore`, shut down via `signal.NotifyContext`:
1. **journal tail** — `journal.TailFollow` in a capped-backoff restart loop (journalctl -f never self-exits; a scanner error would otherwise silently kill ingest for the process lifetime). Only started when journald sshd is actually readable (`journalSSH`); the other three always run.
2. **cowrie ticker** (5s default, `interval`) — `cowrie.IngestFileAppend` + `capture.Runner.Run`.
3. **purge ticker** (24h + once at startup) — `store.MaintenancePurge` + `PurgeOldSourceFiles`.
4. **artifact retry worker** (10s poll) — `capture.ArtifactWorker.Run`, retrying failed quarantine fetches with lease-based claiming and a 5-attempt budget (schema v17).
5. **store timestamp backfill** — first repairs pre-v19 artifact provenance/schedules, then migrates legacy event times into the v20 exact nanosecond column. Both use bounded transactions and durable ID cursors; malformed rows fail closed without stalling later rows.

### Ingest (`internal/ingest/{cowrie,journal}`)
Both sources: parse text → `[]*models.Event` → assign actor IDs → persist. Two modes per source: full-replace (`IngestFile`, `--replace`) and incremental append (dedup-based, used live).

- **Incremental Cowrie ingest is genuinely O(new bytes)**, not O(file size). `IngestFileAppend` persists `IngestState{Inode, Offset, HeadSig}` and seeks to the offset. Rotation is detected three ways: inode change, size < offset (truncate), and a sha256 of the first 512 bytes (catches copytruncate — same inode, replaced content). Offset advances by bytes *actually consumed*, never `fi.Size()` (Cowrie may append mid-Stat). Uses a bounded line reader (not `bufio.Scanner`) so one >2MB attacker line is skipped-but-consumed rather than wedging ingest forever.
- **HASSH stamping is essential** (`stampHASSH`, `persistBindings`): Cowrie emits the HASSH fingerprint only on `cowrie.client.kex`, which isn't a persisted event. Ingest extracts session→hassh bindings as a side channel and back-fills `e.HASSH` onto each session's real events. Without this, every Cowrie actor would cluster by IP, defeating the fingerprint premise.
- Shared dedup (`store/events_dedup.go` `IterateEventIdentitiesByTS`) has a load-bearing SQLite-planner workaround: it filters `WHERE ts IN (...)` only and re-applies the `source` filter in Go, because *any* `source=` predicate makes the planner do a full-source scan. Don't "simplify" it back into SQL.

### Actor model (`internal/actor`)
An actor is a **clustered attacker identity, not one-per-IP**:
- `journal:<src_ip>` — clustered by IP (their attempted-username distribution is their personality).
- `cowrie:<hassh>` — clustered by HASSH (one HASSH across 3 IPs = one actor); falls back to `cowrie:<src_ip>` when HASSH is absent.
- **Admin IPs are excluded from all clustering** (`AdminSet` → `netmatch.Set`, accepts IPs + CIDR like Tailscale `100.64.0.0/10`) so you don't classify yourself as an attacker.
- `playbook.go` labels behavior (`fast_dictionary_spray`, `crypto_target`, etc.) from username taste × attempt rate; `ProbeScore` (0–100) and `Confidence` (fixed tiers) feed dashboard sort + report vetting.
- **Two labels cover the connect-only majority**: `handshake_scan` (connected, never authenticated) and `scanner_tool` (authenticated but no credential *taste* to profile). Before they existed 74% of live actors sat at `unknown`; they are 96% of cowrie actors on prod. Neither ends in `_spray`/`_enum`, so `abuseipdb.Vet` refuses them for free — a scanner can never be reported as a brute-forcer. Don't "simplify" the suffix check into an allow-list that would have to be updated for every new label.
- `actors.flags` (schema v18, `models.ActorFlag*`) persists the event-mix bitmask so ingest folds fresh events into the stored aggregate instead of re-scanning the actor's whole history — this is what took the live daemon from 22% CPU to 2%. Rows written before v18 carry `flags=0` and are repaired by a one-shot full re-scan on their next touch; `reclassify` does the same. An actor whose events retention already purged can never be rebuilt (no data) — `planReclassify` counts those as `Unrebuildable` rather than silently skipping them, and `MaintenancePurge` now deletes them outright (see Store).

### Store (`internal/store`, largest package — SQLite via `modernc.org/sqlite`)
- **Writes are serialized at the app layer by a single `writeMu`** (`WithTx`/`execWrite`), *not* by a 1-connection pool. The pool is 8 connections in WAL mode so reads stay parallel with the single writer. Every write goroutine (journal tail, cowrie ticker, purge, web) goes through `writeMu`. The DB file is chmod 0600 (it holds attacker passwords).
- **Migrations** are a linear ladder v1→v21 in `sqlite.go`, each guarded `if current < N` and stamped `INSERT OR IGNORE` into `schema_migrations`. A base `CREATE TABLE IF NOT EXISTS` block runs first; old DBs get guarded `ALTER TABLE ADD COLUMN` steps. **Most migrations are index tuning driven by EXPLAIN QUERY PLAN** — read the comments before touching them (e.g. v9 *drops* a write-amplifying index; v10 replaces `idx_events_actor` with composite `(actor_id, ts)`). The feature tail is v16 session side channels, v17 artifact retry state, v18 actor flags, v19 capture evidence timestamps/leases, v20 `events.ts_unix_ns`, and v21 a partial index of unconverted event timestamps. v20 is schema-only during `Open`; long-running web/live modes backfill legacy rows in bounded transactions so startup never rewrites the events table. Mixed event readers merge the normal timestamp indexes with an exact RFC3339 parser over that shrinking legacy index; avoid millisecond buckets, whole-window Go buffers, or forcing the global legacy index on actor-specific reads. To add schema: append the next version and update this figure.
- Lazy tables (artifacts, ip_enrichment, bazaar_uploads, session_hassh, abuseipdb_reports…) are each created on first use via a `sync.Once` to avoid DDL under `writeMu` on hot calls. When batching writes across several of these in one `WithTx`, call the `ensure*` helpers **before** opening the transaction — they take `writeMu` via `execWrite`, and `writeMu` is not reentrant, so ensuring inside the tx deadlocks (see `RecordSessionBindings`).
- `MaintenancePurge(retentionDays)` deletes events in **5000-row chunks, each its own transaction**, releasing `writeMu` between chunks so a first purge of an aged DB doesn't stall ingest for minutes; then unlinks the corresponding evidence files and runs `PRAGMA optimize` (also run once at `Open` after migrate) so the plan-sensitive queries keep their intended index plans as cardinality shifts. It then sweeps **orphan actors** — rows whose every event the purge just deleted. Actors are derived data; an orphan keeps a stale `event_count` and a playbook frozen at whatever the classifier last said, inflates the dashboard's actor count, and can never be reclassified because there is nothing left to re-scan (prod carried 103 such rows, 102 reading `unknown` — the entire residual unknown population). Three guards make it safe and **all three are load-bearing**: `last_seen < cutoff` (so the ingest tick's just-created actor is never raced away), no surviving events, and no operator annotation (`campaigns`/`notes` are human work and deliberately outlive the telemetry). Unlike events it is one transaction, not chunked — actors is bounded by distinct attacker identities, thousands against a million events.
- **Windowed reads for the UI are bounded.** `EventsSinceCapped(since, limit)` returns at most `limit` (default `defaultWindowEventCap`) newest-first events **plus the true window total**, so callers disclose "N of M" instead of materializing a whole 30d window into RAM. `EventsSinceAll` (uncapped) still exists for non-UI use but shouldn't be reached from a poll path — prefer the capped form.

### Geolocation (`internal/web/geo.go` + `geo_mmdb.go`) — two tiers, local first
`mmdbResolver` (MaxMind GeoLite2/GeoIP2 City, path from `geoip.mmdb` or `SHARDLURE_GEO_MMDB`) is **tier 1**; ip-api.com HTTP is tier 2 and only consulted for IPs the database can't answer. Three reasons this matters, all measured on the live deployment: (1) **coverage** — `prefetch` caps the HTTP tier at 48 IPs/call plus a wall-clock budget and only resolves IPs currently on screen, which left ~77% of attacker IPs permanently unresolved; the MMDB sweep in `prefetch` deliberately **bypasses that cap** because memory-mapped reads have no quota. (2) **privacy** — the free ip-api tier is *plain HTTP*, so every attacker IP was disclosed in cleartext, contradicting the no-leak discipline in bazaar/abuseipdb. (3) **air-gap** — completes the story started by vendoring the globe engine. A configured MMDB makes `isEnabled()` true on its own, so geo works with `geo.http` off entirely (zero-egress config); `httpTierEnabled()` is the separate gate for outbound. A missing/corrupt database is **fail-open** (logs, degrades to HTTP, reports via the Settings badge), matching the keyless enrichment providers. Opened once at startup — it backs an mmap that can't be swapped under concurrent readers, which is why the path is *not* a live keystore setting.

### Enrichment (`internal/intel/enrich`) — inbound IP reputation
Seven providers (AbuseIPDB, VirusTotal, GreyNoise, Shodan, AlienVault OTX, IPQualityScore, IPinfo; GreyNoise + Shodan work keyless). Each is a `providerSpec{envVar, keyOptional, buildReq, parse, notFound}` — **adding provider #8 is one file + one row in the `providers` slice** (a `[]provider`, each pairing a `Provider*` id with its spec). `LookupAll` gates every IP through `safeForEnrichment` (rejects private/reserved — SSRF defense) then fans out 7 goroutines into fixed slice indices (stable order), each with a 6s timeout. Cache-then-fetch with 24h TTL; only caches `Configured && Error==""` results so adding a key takes effect immediately.

### Outbound intel (`internal/intel/{bazaar,urlhaus,threatfox,abuseipdb,ioc}`) — the vetting-gate pattern
Each has a single `Vet`/`vet.go` function that **both the CLI and the dashboard call** — policy lives in exactly one place, and **hard-rejects always win over accept signals**. Candidate structs deliberately omit any host/session identifier so nothing leaks to third parties.
- `bazaar` — uploads confirmed-malware payloads to MalwareBazaar; `Vet` enforces abuse.ch policy (no tty transcripts, no SSH keys, ≤10 days old, confirmed-malware OR fetched-during-attacker-session). **Candidate selection must never be tighter than `Vet`** — a sample dropped before the gate is rejected by an invisible second policy with no reason an operator can read. `Vet` therefore exports `MinSampleBytes` (64) and `ShareableOrigins()`, and `store.ArtifactsForShare`/`ListArtifactsAggregatedSince`/`PayloadShareable` take a `store.SharePolicy` built from them (passed in, not imported — `store` must not depend on `intel/bazaar`). The pre-filter drifted twice and each drift silently hid real payloads: `origin LIKE '%download%'` excluded `quarantine_fetch`, the capture runner's own fetches (10 payloads, 18.6 MB), and `size_bytes > 1024` sat 16× above Vet's floor (13 dropper scripts). A zero-value `SharePolicy` marks **nothing** shareable, so a forgotten argument fails closed. The dashboard's **pending stat counts under the same policy + freshness window** (`BazaarUploadStats(since, pol)`) — it kept a private legacy filter after the selection fix and claimed 148 pending against a real pool of 30. Relatedly, **shareability is a property of the sha group, not of the newest row** (67 prod hashes mix origins — same payload recorded by both the cowrie hook and our fetch, and a newer row can be a *failed* re-fetch): the server answers it group-level and the dashboard consumes that flag instead of re-deriving it from `origin` in JS, which is what cost two family-identified droppers their share button while the CLI was selecting them. `--limit` bounds **submissions inside `Share`, after `Vet`** — truncating the candidate slice first spent the whole budget on already-shared hashes at the top of the newest-first list and uploaded nothing. Every local skip reports through `OnProgress`; a bumped `skipped` counter with no per-sample line is unreadable. Family attribution is `elf_family.go` — **precision-first Tier-A anchors** (plus XOR-decoded config/credential tables and UPX detection), shared with `threatfox`'s Malpedia gate. It deliberately yields *no* family rather than a guess: on the live corpus that means scripts resolve (`redtail`, `Coinminer`, `Traffmonetizer`) while packed and Go-built ELFs stay unnamed. That is the design, not a gap — a wrong `malware` label is what gets the shared abuse.ch account banned.
- `abuseipdb` — reports confirmed brute-forcers; `Vet` requires `_spray`/`_enum` playbook AND ProbeScore ≥ floor AND ≥20 events AND ≥3 users, excludes admin/private IPs (account-strike defense), and hard-rejects anything **last seen more than 7 days ago or carrying no timestamp at all** — a report asserts present-tense abuse, and the suggestions widget was offering IPs dormant 31–50 days because `ReportCandidate` had no date for the gate to read. Staleness is checked *before* the accept signals, so probe 100 and six-figure event counts cannot carry a dormant IP through. Tightenable via `VetOptions.MaxAgeDays` (1..6), never loosenable, exactly like `bazaar.FreshnessDays`/`urlhaus.ActiveDays`. `store.ReportPoolMaxAge` bounds the pool query to match; the pool is an optimisation, `Vet` is the policy. `--limit` bounds **reports inside `Report`, after `Vet` and dedup** (`Options.MaxReports`) — the same fix as `bazaar`'s `MaxUploads`, and for the same reason: candidates are ordered worst-offender-first, which on any deployment with history is also already-reported-first, so truncating the slice first spent the budget inside the re-report window and reported nobody. **The candidate's `LastSeen` must be the primary IP's own observation (`store.PrimaryIPLastSeen`, from `actor_ips`), never `actor.LastSeen`** — the actor figure is the max across a HASSH cluster, and a 4-day-old cluster-mate carried a 17.7-day-dormant primary IP through the gate on prod. Missing map entry = zero time = Vet-rejected, so absent data refuses rather than reports.
- `urlhaus` — submits the malware-distribution **URLs** the payloads came from (bazaar ships the files). `Vet` requires a real `http(s)` URL (this is what rejects the capture runner's `cowrie-download:`/`cowrie-event:` dedup pseudo-keys), `origin=quarantine_fetch` + `status=fetched` + a payload hash ≥ 64 B (first-hand proof the URL served something), a public IP/hostname (RFC1597/6890 is an explicit policy requirement), no shorteners, and a fetch inside `active_days` (default 3, may only tighten). `urlhaus_submissions` is a dedup ledger and is **never purged**; the SQL in `store.URLhausCandidates` must stay identical to the Pending subquery in `URLhausSubmissionStats` (they drifted once and the UI count disagreed with the CLI's list). `--limit` bounds **submissions inside `Share`, after `Vet` and dedup** (`Options.MaxSubmissions`) — it was a SQL `LIMIT` on the candidate query, the same pre-gate truncation as the bazaar/abuseipdb twins in different syntax; the CLI now collects unbounded (`URLhausCandidates(activeDays, 0)`). Surfaced on the **Blue Team** tab (`panel-urlhaus`) — the panel renders `Vet`'s per-candidate decision *including the rejection reason*, and `handleURLhausSubmit` re-runs the gate server-side so the button (and a hand-crafted `?url=`) can never bypass policy; `urlhausBatchMu` stops a double-click racing the ledger.

- `threatfox` — submits the malware-delivery **IOCs** (url + host `ip:port`/`domain` + sha256) for payloads ShardLure fetched first-hand, the third abuse.ch give-back on the same key. `Vet` is the urlhaus gate plus **one hard extra: the classifier's family must resolve to a real Malpedia label** (`internal/intel/threatfox/malpedia.go` — only `mirai→elf.mirai`, `gafgyt→elf.bashlite`, `redtail→elf.redtail`, `xmrig→elf.xmrig`, each verified against the live `malware_list`; every other family is unsubmittable, never guessed — a wrong `malware` label is exactly the junk that bans the shared account). Host classification is shared with urlhaus via `intelutil.PublicHostKind`/`HostNormalise` (the two gates MUST agree on "public payload host"; extracted so they can't drift). **IPv6 hosts must go through `net.JoinHostPort`** — the naive `host+":"+port` renders the malformed `2606::1111:80` (found in adversarial review). `submit_ioc` responses: `ok`/`duplicated` arrays = success (record in the never-purged `threatfox_submissions` ledger), `ignored` or any non-`ok` `query_status` = failure (do NOT record, so a fixed run retries). `--limit` bounds submissions inside `Share` (`Options.MaxSubmissions`, counts candidates, dedups per-IOC); `store.ThreatFoxCandidates` SQL == `threatfoxPendingSQL`. Blue Team `panel-threatfox`, server-side re-vet in `handleThreatFoxSubmit`, `threatfoxBatchMu`.

**The one-key invariant.** abuse.ch issues a single Auth-Key per account covering MalwareBazaar, URLhaus *and* ThreatFox. There is exactly one resolution path on each side — `web.abuseCHKeyLive()` (with `bazaarKeyLive()` as a thin alias) and `cmd.abuseCHKey()` — both DB > env > config. Deliberately **no `urlhaus`/`threatfox` key setting exists** in the keystore registry: a second field would let them silently drift and half-arm sharing.

**CLI subcommands must read the keystore, not config/env.** `main.go` seeds the keystore *from* config at startup, never the reverse — so a value saved in the dashboard Settings panel exists **only** in `app_settings`. Every outbound CLI path therefore takes `*settings.Keystore` and resolves DB > env > config: `share bazaar` / `share urlhaus` via `abuseCHKey()`, `report abuseipdb` via `resolveAbuseSettings()`. This bit three times before it was fixed everywhere — and for AbuseIPDB it was not just the key: the **enable flag, categories, comment, min-probe and rewindow** were all config-only, so a dashboard-configured deployment got a CLI that refused to run ("report_enabled is false") and would have reported with the wrong policy. `resolveAbuseSettings` mirrors the server's `abuse*Live()` accessors one-for-one; flag defaults are seeded from it so an explicit flag still wins.
- `ioc` — emits **byte-stable** STIX 2.1 (deterministic UUIDv5 IDs) so re-exports diff cleanly.

### Payload hash intel (`internal/intel/vt`) — quota-shaped, not poll-shaped
VirusTotal's **file** endpoint (distinct from the IP provider in `intel/enrich`). The free tier is ~4 req/min, which dictates the whole design: lookups are **on-demand only** (never a background sweep), verdicts cache in `payload_intel` for 30d (7d for not-found) because a file hash is immutable, concurrent lookups of one hash collapse via a `sync.Map` of `sync.Once`, and errors/429s are **never cached** (a transient rate-limit must not blank a verdict for the TTL — a stale cached value is returned instead). HTTP 404 is a first-class `found:false` result, not an error. Two endpoints by design: `/api/intel/payload/vt` spends quota; `/api/intel/payloads/vt/cached` is cache-only and safe for list renders. Only the sha256 is transmitted — the file is never uploaded.

### Settings keystore (`internal/settings/keystore.go`)
Leaf package (imports only `store` + stdlib). Precedence on read: **DB value → env var (`SHARDLURE_*` only) → ""**. API keys and knobs (`ui.theme`, `abuseipdb.*`, `home.*`) live in the `app_settings` table, read **live at request time**, so a dashboard Settings save takes effect **without restart**. `main.go` seeds it from config/env at startup so existing systemd deployments are unaffected.

### Capture (`internal/capture`)
Every 5s: extracts URLs from recent commands and quarantine-fetches them, syncs Cowrie's downloads + ttylogs into `evidence/{quarantine,cowrie,cowrie-tty,meta}` (0700/0600). **`SafeFetcher` is SSRF-hardened**: `safeDial` re-resolves DNS and validates the actual IP *at dial time* (closes the resolve→connect TOCTOU / DNS-rebinding hole), size-caps downloads, and **never executes content**. Dedup memos skip the copy+hash *before* the dedup query to avoid GB/min write amplification.

## Web layer (`internal/web`)

- Assets are `go:embed`ed (`embed.go`): `index.html` + `intel.html` (two dashboards), `themes.css`, `cobe-globe.js`/`cobe-boot.js`, `vendor/vis-network.min.js`, `vendor/cobe.esm.js` (vendored globe engine — no CDN), the brand assets `logo.svg`/`logo-180.png`/`favicon.ico`, and **`fonts/`** (`fontsFS`: latin woff2 subsets of the six families the themes resolve + a generated `fonts.css`, served by `handleFont` under `/fonts/`). Every CSP fetch directive is `'self'` — fonts were the last third-party host; `scripts/fetch-fonts.sh` regenerates the directory with **content-hashed file names** (`inter-var-<sha8>.woff2`, so the route's `immutable` cache header is honest; the test checks name against bytes), and `TestFontsAreSelfHosted` pins that every quoted family in a theme stack is vendored, so adding a font to `themes.css` without re-running the script fails the build. HTML is served behind auth; static JS/CSS, fonts and the brand assets are unauthenticated — a favicon is requested before any token exists, and none of them carry telemetry. **vis-network is loaded on first use** (`ensureVis()` in the pivot-graph refresh), not from `<head>`: it is 689 KB for a third-tab panel.
- **Two dashboards:** `index.html` = the globe view (polls `/api/dashboard`); `intel.html` = the tabbed analyst console (Overview/Blue/Red/Settings, full `/api/intel/*` surface).
- **Auth is bimodal** around `SHARDLURE_DASH_TOKEN` (read live via the keystore, `crypto/subtle` compare): `/api/*` is **header-only** (`guard` → `Authorization: Bearer`). Read endpoints wrap that in `guardRead`, which additionally rejects anything but GET/HEAD **with an `Allow` header** — a 405 without one tells the caller nothing (`route_method_test.go` pins both the wrapper and that the bulk of `/api/*` uses it). Mutating endpoints (`*/upload`, `*/submit`, `*/report`, `/api/settings/save`…) take bare `guard` and check the method themselves. `/debug/*` uses `guardDebug`, which in token-less open mode additionally requires a loopback TCP peer (pprof never rides along with the open-dashboard convenience mode); the two *page* routes accept `?token=` in the query too (a browser nav can't set a header — the page then stashes the token and uses the header for all API calls; `fetch` is monkey-patched to inject it). Startup **refuses to bind** if the token is empty AND the listen addr is a public routable IP; otherwise open (designed for Tailscale/loopback).
- **Dashboard query caching lives here, not in `store`** — and it exists for a reason (comments document prior OOM/IO). `summaryStatsCached` is now a **combiner over three tiers keyed by how fast each value changes**: `liveSummaryStatsCached` (`statsTTL` 10s: event/actor counts, intent/playbook counts, 72h hourly-by-kind, Cowrie liveness), `distributionSummaryStatsCached` (`distributionStatsTTL` 1m: kind/source distributions) and `lifetimeSummaryStatsCached` (`lifetimeStatsTTL` 5m: unique IPs, countries, top IPs/users/commands, all-time session count — the unbounded all-history scans that were the remaining ~2.7s behind every `statsTTL` expiry on prod). `countriesCached` rides `lifetimeStatsTTL` too. `TestSummaryCacheTTLsAreTiered` pins the ordering; don't collapse a lifetime value back into the 10s tier. **Two rules inside the tiers:** a degenerate lifetime value (empty country list, zero countries while geo is enabled, a failed session count) is stamped with `lifetimeStamp(false)` so it expires on `statsTTL` — the geo table is filled asynchronously by the very handler that reads it, and caching the cold first read for 5 min froze the intel Attack Geography panel; and the combiner **serves a tier's last-good value when its refresh fails** (only a tier that has never succeeded is fatal), the same policy as `hasshCoverageCached`/`topCountriesCached`. `dashExtraCachedValues` (10s TTL) memoizes the two remaining full-window scans `/api/dashboard` used to run uncached (`HourlyEventCounts(72)` + `RecentShellSessions`); `eventsForWindowCached` (15s TTL, per-window, single-flight, **LRU-bounded to `maxEventsCacheEntries`=4 entries** so an authenticated client asking for many distinct exact windows cannot pin unbounded RAM; expired entries are evicted before live ones, last-good is served on a transient store error) memoizes the *bounded* windowed event slice shared by mitre/ttp/deobf/graph/wordlist/ioc — it returns `(events, total, err)`, and every intel handler calls `discloseWindowTruncation(w, len(events), total)` to set an advisory `X-ShardLure-Window-Truncated: returned/total` header when the cap bit. Don't remove these without understanding the poll-storm they prevent (N widgets × full scan every 5s).
- **`hasshCoverageCached` is the one aggregate with its own, much longer TTL (5 min).** `store.HASSHCoverage` is a COUNT + SUM over every cowrie event ever ingested with no `ts` restriction, so its cost grows without bound as the DB does: measured at **1.28s on prod's 1.06M rows, ~10× the next-largest dashboard query** (`TopCountriesByHits`, 0.13s), and the biggest single contributor to a 4.6s `/api/dashboard` on each cache expiry against 4ms warm. With a 5s poll and a 10s `statsTTL`, roughly every second poll paid it. The figure is a *lifetime ratio* that moves fractions of a percent per hour, so minutes of staleness are invisible. Don't fold it back into `statsTTL`, and don't "fix" it with an index on `(source, hassh)` — v9 dropped a write-amplifying index for a reason and every event insert would pay for it.
- **Frontend accessibility + responsive contracts are pinned by `frontend_a11y_test.go`** (from `docs/FRONTEND-UI-AUDIT-2026-09-07.md`, every finding reproduced in a real browser before it was fixed): collapsible panels are `<h2><button class="panel-toggle" aria-expanded aria-controls>` (a collapsed body is `visibility:hidden`, not just `max-height:0`, or its buttons stay tabbable); no `outline:none` anywhere — `themes.css` owns one `:focus-visible` ring per theme via `--focus-ring`; every static control has an accessible name and the generated Settings rows use `aria-labelledby` → `labelId(key)`; the search input is a `role=combobox` whose `aria-activedescendant` follows the palette selection; the two modals are native `<dialog>` opened with `showModal()` (focus trap, Esc, inert page, focus restore come from the browser); **every intel poller goes through `pollEvery`** (skips ticks while `document.hidden`; on return each runs only if more than half its period has elapsed, so a rapid hide/show cannot fire overlapping bursts) and `intel.html` may contain exactly one bare `setInterval(` — the one inside it; `index.html`'s single poller carries the same `document.hidden` guard and a last-run check; the download controls are `<button>`s, not href-less anchors; no inline `grid-template-columns` (an inline style beats every media query — `.stats.cols-5`); both pages have a ≤760px layout (intel: sidebar becomes a top strip, tables get a min-width and scroll in their panel; index: rails go static and the page scrolls, the live feed is *not* hidden, the globe's phone rules live in `themes.css` beside its desktop ones because that file loads last); `--dim`/`--dim-2` clear 4.5:1 against bg *and* every panel surface per theme (`TestDimTokensMeetContrast` computes it) and nothing is set below 10px; side-stripe `border-left` accents are banned. Legacy-palette `rgba(200,152,40,…)`-style tints were tokenised to `color-mix(in srgb, var(--token) N%, transparent)`, picking the token from the rule's own text colour.
- **Density toggle** — comfortable (14px/12px) is the default; compact restores the original 13px. Unlike the theme it is **`localStorage` only** (`shardlure_density`, applied by an inline pre-paint script so there's no flash) — it is a per-screen viewing preference, not a deployment setting, so it deliberately has no keystore key.
- **Themes: 3 implemented** — `signal` (default; supports `data-mode="dark|light"`), `meridian`, `sprite`. `themes.css` defines exactly those and `validateSetting` hard-rejects anything else. Persisted as keystore `ui.theme` (+ `ui.mode` for Signal), server > localStorage, synced across tabs via `BroadcastChannel`. **One globe engine (Cobe)** for all themes — globe.gl and the Dragon theme were removed in v2.0.0.

## Performance

The README's four perf claims (incremental ingest, batched writes, dashboard query caching, actors indexes) are all **real and correctly implemented**.

**Fixed 2026-07 (a further perf pass — do not re-introduce the old behavior):**
- **Bounded windowed reads.** `EventsSinceAll` used to be `SELECT … WHERE ts >= ?` with no LIMIT, and `eventsForWindowCached` pinned the whole slice in RAM — a 30d wordlist poll on a multi-million-row DB was a full scan + hundreds-of-MB allocation. Now `EventsSinceCapped` bounds the fetch (`defaultWindowEventCap`) while reporting the true total, and handlers disclose truncation via the `X-ShardLure-Window-Truncated` header. Don't route a poll path back through uncapped `EventsSinceAll`.
- **The 5s landing path is fully cached.** `HourlyEventCounts(72)` and `RecentShellSessions` no longer run uncached on every `/api/dashboard` poll — they're behind `dashExtraCachedValues` (see Web layer).
- **Planner stats + pool tuning.** `PRAGMA optimize` runs at `Open` and each purge; `SetMaxIdleConns(8)` + `ConnMaxLifetime(1h)` stop pool churn.
- **Batched side-channel writes.** Per-tick session bindings (hassh/duration/arch/tty) commit in one `RecordSessionBindings` transaction instead of N separate `writeMu` acquisitions ahead of the event insert.

**Fixed 2026-09 (cache tiers + frontend):** the summary-stats cache was split into 10s/1m/5m tiers (see Web layer) so the 5s landing poll no longer drags the all-history aggregates along on every `statsTTL` expiry; the windowed-events cache got a hard entry bound; and the two dashboards stopped polling from hidden tabs, loading vis-network eagerly and fetching typography from Google on every page load.

**Known remaining (LOW, intentional):** `HourlyEventCounts`/`…ByKind` group on `substr(ts,1,13)` and `DistinctGeoCountryCount` does `COUNT(DISTINCT json_extract(...))` — neither can use an index for the *aggregation*, but the `ts >= ?` restriction is index-served and both are now well-cached, so leaving them avoids risking the working plan. Don't "optimize" these into a form that drops the `ts` index restriction.

## Conventions observed in this codebase

- Unknown CLI flags are **fatal, not ignored** (a typo like `--repalce` silently appending was a real bug — see `cmdIngest`). Match that: validate flags, don't swallow.
- **Config resolution has a system fallback, and it is not cosmetic.** `config.Load("")` prefers the invoking user's `~/.local/share/shardlure/shardlure.yaml`, then falls back to `/etc/shardlure/shardlure.yaml` or `/var/lib/shardlure/shardlure.yaml` (`resolveConfigPath`). The systemd unit passes `SHARDLURE_CONFIG`, but an operator shell does not: without the fallback `sudo shardlure share bazaar` opened an empty database in root's home *beside* the real 1M-event one and reported "no candidates" — indistinguishable from a broken feature, on every manual outbound run (there are no timers; all sharing is manual). A user who has their own config always keeps it, an explicit `-config` always wins, and an unreadable system candidate is skipped rather than fatal so a non-root CLI still works.
- Comments here explain *why*, often citing the bug a line prevents. When changing such code, preserve or update the rationale — several guards look removable but aren't (the dedup `source`-in-Go filter, the offset-by-consumed-bytes, the `writeMu`-not-1-conn choice).
- Interfaces decouple `intel/*` from `store` (`UploadRecorder`, `ReportRecorder`, `KeyLookup`) — keep intel packages free of a direct `store` import.
- Secrets are never logged or returned raw; the settings API masks them (`maskSecret`) and reports only a db/env/unset source badge.
