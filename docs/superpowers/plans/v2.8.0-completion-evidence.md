## Task 2 — submission-ledger exact ordering

- Real Record/List/Stats regressions reproduced older-first order and wrong
  latest instants in Bazaar, URLhaus, and ThreatFox. Malformed history could
  silently disappear behind LIMIT/MAX. The joined Bazaar history was affected.
- Additive v22 creates nullable canonical keys and native/legacy indexes in one
  schema transaction. Startup preserves original timestamps, statuses, provider
  metadata, and dedup rows; bounded background repair populates only keys.
- Repair uses one atomic transaction for reads, writes, and per-table cursors,
  at most 1,000 rows per batch. Malformed rows remain recorded and visible as
  sanitized read errors, while repair advances to later rows. Cancellation and
  failed transactions report no committed progress.
- Focused tests pass for all fraction widths, offsets, nanosecond differences,
  deterministic ties, populated pre-v22 reopen, optional tables, partial
  repair/restart, rollback, invalid-then-corrected rows, concurrent writes,
  native-key validation, and startup backfill orchestration.
- EXPLAIN confirms native LIMIT/latest index paths plus the shrinking legacy
  index. List/stats allocations for 10 -> 3,010 migrated records: Bazaar
  68 -> 70, URLhaus 80 -> 82, ThreatFox 89 -> 91.
- Final full Go suite PASS (store 76.988s, web 23.281s), focused race PASS
  (store 25.502s, CLI 1.647s), and vet PASS. The first whole-suite run exposed
  the inconsistent v20 fixture described below; its corrected regression and
  the subsequent full suite pass. Post-commit task verification remains pending.

Rulings:

- Standard-SQL triggers invalidate stale keys and rewind repair cursors when an
  old writer updates a timestamp without updating its key. Cost if wrong is an
  extra bounded repair pass; original ledger and dedup state stay intact.
- Require strict RFC3339 with at most nine fractional digits. Tests reproduced
  Go silently truncating extra precision and accepting invalid timezone fields.
  Cost is a sanitized error for unsupported historical syntax instead of an
  invented instant; the raw value is preserved.
- Adjust the v20 upgrade test fixture to remove all migration stamps >=21.
  Leaving v22 in a simulated v20 database suppressed the migration under test.
  This is a fixture-only correction; no-rewrite/index assertions are retained.
