## Task 4 — durable file-capture store contract

- The real old archiver reproduced only 200 archived files out of 406 inert
  download events. The baseline fixture and failure log are preserved in the
  plan workspace for the required Task 5 end-to-end integration regression.
- Additive v24 records per-event file jobs, provenance, normalized native
  basenames, bounded retries, persistent lease tokens, and terminal diagnostics.
  Discovery streams bounded primary-key/byte pages and commits each checkpoint
  with its work. It retains late timestamps and survives reopen without loss.
- Independent stores claim a job only once. Expired/replaced leases and observed
  clock rewinds cannot revive old tokens. Completion and per-event artifact
  association commit together; an existing quarantine-fetch row sharing the
  delivery URL is unchanged. Source protection uses a partial indexed lookup.
- File and command pages have a 4 MiB byte budget. Command fanout/work limits
  also bound transactions; malformed commands are durably diagnosed rather than
  stalling later discovery or echoing raw timestamps. Native filename bytes are
  preserved, including literal Unix backslashes.
- Hashless files can be archived without inventing remote-fetch freshness;
  their unknown freshness survives observation touches and timestamp backfill.
- Full Go suite PASS (store 77.160s, web 24.086s), vet PASS, and capture-focused
  race checks PASS over three runs (store 95.983s, capture 3.236s). Post-commit
  verification PASS at 05923c0: store 77.908s, capture 2.309s. Task 4 complete.
  Runner/filesystem integration remains Task 5 after 6.

Rulings:

- Preserve the failing old-runner fixture outside the active suite during this
  store-only task; Task 5 must turn its 406-event expectation green. Cost is an
  integration check to carry forward, not a claim that the runner is fixed yet.
- Add a terminal command-discovery diagnostic table to address the reproduced
  malformed-row stall. Task 5 retention and Task 11 diagnostics must include it.
  Cost is one additive metadata table, not fabricated successful capture.
- Limit command fanout to 512 URLs/2 MiB of URL text and approximately 2,000 URL
  operations per page, finishing the current bounded command. Cost is explicit
  rejection of extreme fanout; original events follow ordinary retention.
- Persist a clock floor and invalidate the matching token on observed expiry or
  rewind. Cost is delayed retry during a large clock correction, never stale
  completion acceptance.
- Preserve unknown remote-fetch freshness when no original expected hash exists.
  Cost is withholding sharing eligibility for unverified provenance while
  preserving archived bytes and observation metadata.

## Task 6 — confined filesystem access and ownership preflight

- Actual pre-change regressions showed unsafe SQLite links/shared parents being
  accepted, a sidecar-symlink failure after database mutation, and URI punctuation
  breaking literal filenames. Ownership/path checks now precede SQLite writes,
  migration and permission changes; file URI construction encodes filenames.
- Linux reads are anchored to descriptors, reject all supplied symlink/magic-link
  components and hardlinks, and inspect type before opening for data. Exclusive
  outputs are private and non-executable. Unsupported platforms/filesystems fail
  explicitly, without path-based fallbacks.
- Publication uses no-replace rename, durability checks and post-sync identity
  verification. Regressions cover existing files and empty/nonempty directories,
  late fsync failure, root/file replacement, unsafe ancestors and staged modes,
  FIFO/device refusal, and descriptor leaks. No failure deletes uncertain output.
- Full Go suite PASS (store 82.962s, web 25.001s), vet PASS, and five repeated
  confinement/ownership race runs PASS (safefile 1.466s, store 5.799s). All packages
  and the application cross-build for Linux AMD64, ARM64 and ARMv7. A >2 GiB
  sparse-file characterization passes in a 32-bit test process.
- Read-only production compatibility metadata was inspected; no services, owners,
  configuration or collected data changed. Post-commit verification PASS at
  f29a6e7: safefile 0.044s, store 72.086s. Task 6's local implementation is complete.
  Actual cross-account permission validation remains a Task 16 release gate.

Rulings:

- Use injected ownership metadata locally; perform real cross-account validation
  in Task 16's disposable guest. Cost is a later platform/account integration
  check, which remains mandatory before release.
- Reopen checked O_PATH descriptors through verified kernel procfs, never a
  replaceable supplied name. Cost is requiring Linux procfs; this avoids opening
  devices/FIFOs to discover their type.
- Reject child mount crossings and unverified filesystems. Cost is requiring
  separate configured roots for different supported mounts.
- Add output-namespace validation, including before existing-file adoption.
  Cost is refusal of insecure output layouts; read-only source roots may remain

- Keep test fixtures private through shared test-only setup. Cost is stricter

  Cost is rejecting replaceable output paths; read-only roots retain descriptor

## Task 5 — durable archiving and retention integration

- Actual runner/worker regression now archives all 406 inert download events
  across restart, including late timestamps, without changing original bytes.
- Leased/pending jobs and enabled discovery checkpoints hold required source
  data. Disabled discovery releases only undiscovered history, not queued work.
- Capture publication uses private temporary files, verified hashes, no-overwrite
  finalization and fenced durable completion. Existing blobs after a failed
  completion are verified and adopted only when identity is known. Hashless
  missing-source recovery never guesses an association or fetch provenance.
- Raw scans stream directory names, use durable deduplication, and never stamp
  local observations as successful remote fetches. TTY indexing/persistence
  errors are surfaced and retried; transcript derivatives publish atomically.
- Retention preserves note-only actors, pending URL work, shared-file references
  and derivatives. Artifact cleanup uses bounded transactions and requires an
  explicit evidence root before deleting bytes through confined descriptors.
  Outside-root, symlink and active-database targets fail closed. Terminal job
  diagnostics age out only after their events are gone and the outcome ages out.
- Regression failures were observed before fixes, including arbitrary-path
  deletion, the late-page transaction rollback, queued URL deletion, shared
  transcript deletion, hidden TTY failures and overwriting quarantine bytes.
- Full Go suite PASS (store 90.582s, web 24.507s); vet and all-package Linux
  AMD64/ARM64/ARMv7 and Darwin ARM64 builds PASS. Full capture/store/safefile
  race suites PASS (48.457s/249.134s/1.130s). Post-commit checks follow the commit.

Rulings:

- Preserve ambiguous legacy notes, including note-only actors, rather than
  treating annotation text that resembles a generated summary as disposable.
- Raw directory files prove local observation, not remote fetch freshness;
  unverifiable provenance remains ineligible for automatic sharing.
- Harden legacy copy and quarantine publication alongside the new file worker:
  the reproduced overwrite/symlink paths share its evidence namespace.
- Source cleanup recognizes only closed SHA-named files. Unrecognized files are
  conservatively retained instead of assuming permission to delete them.
- Retain paused/stalled URL work until terminal, just as pending file work is
  retained. Cost is visible disk/backlog growth, not silent lost work.
- Empty EvidenceRoot means metadata-only retention; live capture supplies the
  resolved root. Standalone store callers cannot delete arbitrary DB paths.
- Guard only quarantine finalization/recording, keeping network work outside the
  retention critical section. Cost is a narrow internal publication callback.

## Task 7 — consistent non-migrating SQLite snapshots

- New snapshot API uses a dedicated read-only source connection with a pinned
  read transaction and bounded SQLite online-backup steps. Source migrations,
  backfills and raw main/WAL/SHM file copying never run on this path.
- Finalized snapshots are standalone DELETE-journal databases. Verification uses
  a protected descriptor through a read-only VFS, never reopens an untrusted
  checked filename, preserves bytes/directory entries, and does not migrate.
- Fixed-registry counts, SQLite integrity, supported schemas, and bounded
  evidence metadata are checked. Evidence iteration includes file-job result
  pointers and propagates visitor cancellation. Existing destinations refuse
  replacement; interrupted staging remains available rather than being deleted.
- Actual tests cover simultaneous WAL writes/committed prefixes, literal URI
  punctuation, old/future schemas, annotations/settings/ledgers, malformed
  metadata, repeated/concurrent inspection, read-only directories, descriptor
  lifetime, cancellation/admission, busy retries and backup Finish errors.
- The new tests exposed two additional issues: the pinned VFS destructor corrupts
  its allocator, and recent archived jobs could outlive their evidence file.
  Both were reproduced before their fixes. The snapshot/retention interface now
  protects every durable storage reference without inventing fetch freshness.
- Full Go suite PASS (store 83.285s, web 24.196s); three repeated snapshot and
  retention race runs PASS (66.940s); vet and all-package ARM64/ARMv7 builds PASS.

Rulings:

- Keep one process-lifetime read-only VFS registration with at most eight active
  scoped entries. The pinned destructor mismatches sqlite3_malloc/libc.free;
  entries and SQL handles are still released after every operation. Cost is one
  fixed registration until process exit, avoiding an unreviewed driver upgrade.
- Treat file-job result paths as evidence references and keep newly archived
  bytes until result/event retention permits removal. Cost is conservative
  retention for up to one extra maintenance cycle, not fabricated freshness.
