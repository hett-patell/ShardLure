# ShardLure v2.8.0 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining correctness and operational gaps, preserve collected data, and deliver a verified v2.8.0 release with matching documentation.

**Architecture:** Keep the Go binary, SQLite/WAL, Cowrie file contract, shared Vet gates, and embedded dashboards. Reuse exact-time query branches, add bounded durable work rather than newest-N scans, and isolate backup/filesystem and observability responsibilities. Restore only to a nonexistent destination and never activate recovered services automatically.

**Tech Stack:** Go 1.27, modernc.org/sqlite v1.34.5, existing golang.org/x/sys, net/http, SQLite, systemd, Python installer tests, isolated Ubuntu integration guests.

**Spec:** [Approved completion design](../specs/2026-09-21-reliability-completion-design.md). Read the full spec and repository `CLAUDE.md` before execution.

## Global Constraints

- Never reset production history, remove historical duplicates speculatively, fabricate lost provenance, or use ingestion `--replace` as an upgrade step.
- Preserve existing records, settings, annotations, and submission ledgers.
- Migrations are additive, resumable where necessary, and versioned after v21. Do not change an already-shipped migration's meaning.
- Preserve fail-closed admin-IP, private-address, SSRF, authentication, origin, eligibility, freshness, lease, and deduplication controls.
- Keep writer transactions, materialized query results, queues in memory, diagnostics, and metric-label sets bounded.
- Tests use inert evidence and local provider fixtures. No real public intel submission, malware execution, or attacker-URL fetching is a test prerequisite.
- Development, restore tests, SSH migration tests, and installer tests do not run against the active ARM collection or the developer host's administrative SSH.
- Backup/restore and release procedures do not automatically delete old backups, source evidence, or incomplete recovery output.
- Bundle directories are owner-only `0700` and files `0600`. Manifest format is v1, capped at 64 MiB and 1,000,000 entries. Default operation timeout is 30 minutes.
- Operational sampling defaults: every 5 seconds, 1-second budget, readiness sample maximum age 15 seconds. Expensive gauges refresh at most once per minute.
- `observability.min_free_bytes` defaults to 268,435,456; nonnegative only; `0` disables only the space threshold.
- Preserve the ts-only dedup planner invariant and ensure-before-transaction ordering. Do not introduce an actor/store or intel/store import cycle.
- No new linter, dependency, cloud service, public unauthenticated probe, or automatic production restore is part of this plan.
- Transfer Go/Python sources to a disposable remote guest with the project's tar-over-SSH workflow, never direct scp.

## Review Focus

1. **Clock changes:** forward/backward wall-clock jumps must not validate stale leases or future-dated health samples. Pin in Tasks 4 and 11.
2. **Late I/O failures:** ENOSPC, fsync failure, or a destination appearing at final publication must never yield a successful backup/restore. Pin in Tasks 6, 8, and 9.
3. **Path identity changes:** a source/parent replacement, contained symlink, hardlink, relative alias, or overlapping backup destination must not read outside roots or overwrite existing content. Pin in Tasks 6–9.
4. **Schema and process separation:** verifying an older/future/corrupt bundle must not migrate it or touch the production DB; CLI metrics must not pretend to describe another process. Pin in Tasks 7, 9, and 12.
5. **Adversarial username identity:** a real `_overflow_` username, comma-containing names, and Unicode must not collide with cache sentinels or produce a false exact derived profile. Pin in Task 3.
